### The core ideas

- **Software development is a craft.** Programming isn't merely typing code to satisfy requirements. It requires practice, discipline, judgment, and continuous improvement.
- **Professionalism has three pillars:**  
    **discipline, standards, and ethics.** A professional developer needs all three.
- **Practice deliberately.** Martin emphasizes activities like coding exercises, kata, and practicing techniques outside the pressure of production work.
- **TDD is a fundamental discipline.** The classic cycle is:  
    **Red → Green → Refactor**  
    Write a failing test, make it pass with the simplest solution, then improve the design.
- **Keep code continuously clean.** Don't wait for a large “refactoring phase.” Small improvements should happen constantly.
- **Use automation.** Build, test, and deployment processes should be automated so developers can get fast feedback and reduce human error.
- **Standards create consistency.** Teams should establish agreed-upon engineering practices rather than having every developer work according to personal preferences.
- **Architecture emerges through good design practices.** Clean code, tests, and incremental development make it easier to evolve architecture without massive rewrites.
- **Technical debt is a choice with consequences.** Taking shortcuts can be legitimate, but you should understand the cost rather than pretending the debt doesn't exist.
- **Craftsmanship is social.** Mentoring, pairing, code reviews, teaching, and sharing knowledge are part of becoming a better profession.
- **Ethics matter.** Developers have obligations to employers, customers, users, teammates, and society. You shouldn't knowingly ship dangerous or dishonest software simply because someone asks you to.
- **The profession needs standards.** Martin argues that software engineering should develop stronger professional norms, similar in spirit to established engineering professions.
